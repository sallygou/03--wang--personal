# 订单接口确认说明

> ⚠️ 本文件内容为**教学模拟数据**，不指向任何真实生产接口，仅用于演示协作流程。

## 1. 调用方式

- Method：`POST`
- Path：`/api/v1/order/create`
- 沙箱地址：`https://sandbox.example.com`（模拟）
- 鉴权：请求头 `Authorization: Bearer <token>`

## 2. 必填入参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | string | 用户唯一标识 |
| ticket_type | string | 票种编码（如 EB_STD） |
| quantity | int | 购买数量，取值 1-5 |
| idempotency_key | string | 幂等键，24 小时内同值只生效一次 |
| source_page | string | 来源页面标识（便于统计早鸟票渠道） |

## 3. 返回字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | string | 订单号 |
| status | string | CREATED / PAY_PENDING |
| expire_at | string | 订单支付截止时间 |

## 4. 主要错误码

| 错误码 | 含义 | 建议处理 |
| --- | --- | --- |
| 40001 | 参数缺失或格式错误 | 前端校验字段 |
| 40002 | 幂等键重复提交 | 直接返回原订单，不需重试 |
| 40901 | 库存不足 | 提示用户余票不足并刷新库存 |
| 42901 | 超出调用频率限制 | 页面退避重试 + 提示稍后再试 |

## 5. 调用限制

- 沙箱 QPS 上限：20（模拟值，秒杀场景需评估）
- 幂等窗口：24 小时

## 待对方确认事项

- 幂等键的生成规则由谁保证（建议页面侧生成）
- 20 QPS 上限是否满足活动页峰值
